# Preview integration assessment

The current checkout is Lig 1.4.0 at `7b8a4c8`. At the start, the accessible older source was named `lig-enhanced` in the dotfiles checkouts. After `lig-adv` was added at the project root, the preview and integration files were compared directly against the second reference copy and matched byte for byte. The assessment uses `lig-adv` and its working-tree diff from the Lig 1.3-era import at `1150d8a`. The older checkout is a read-only reference.

| Area | Older reference (lig-adv) | Current Lig | Proposed solution |
|---|---|---|---|
| Completion integration | `engine.rs` attaches a typed target to `Suggestion`, including filesystem, contextual Git and package targets. | `Suggestion` carries kind, display label, insertion, delete count and cursor offset. `Engine::complete` combines built-in specs, generators, native shell answers and file enumeration. | Adapt file and folder suggestions using the existing lexer and the completion request's directory. Leave providers, insertion, ranking and replacement contracts intact. |
| Inline previews | `expanded_layout_at_inner` fits a split in the region above or below input, delegates list sizing to `layout_at` and paints the preview with `draw_with_preview`. | `popup::layout_at` positions a compact list, with an optional description frame. | Reuse the existing list geometry and renderer, allocating adjacent side or stacked frames in the same safe region. |
| Floating previews | The split is owned by one expanded popup. | No candidate preview. The CLI `lig preview` renders a sample list. | Reserve a separate, gapped rectangle relative to the existing list. Keep the list anchored. |
| External commands | Worker executes bounded argv, including bat, chafa, archive tools and overrides. Git diff can pipe controlled input to delta. | `exec::run` runs completion generators with a deadline and unbounded capture. | Give previews a separate bounded runner, explicit argv and shell modes, and reuse the child-group lifecycle pattern. |
| Native preview engines | Third-party programs supply content. Native code formats output and metadata and handles terminal image envelopes. | No candidate preview engines. | Return structured results for text, images, archives and directory trees, with a localized metadata fallback. |
| Rendering | List renderer plus a separate preview frame. Graphics have their own capability probes, envelopes and lifetime tracking. | Lig is a PTY proxy. The vt100 parser models shell output. Popup overlays use cursor positioning, SGR and synchronized output. | Render structured spans and image cells through Lig's overlay cycle, with independent clipping and titles. |
| Scrolling | Dedicated shortcuts and SGR mouse reporting. Reuse guarded SGR wheel framing while the preview owns an area. |
| Configuration | Separate nested preview settings, visibility and cycle, rules, resource bounds and dedicated keys. | Strict, defaulted serde TOML with live theme reload. | Add a default-off table to the existing loader and validate backend modes, dimensions, keys and bounds. |
| Screen restoration | Overlay rows are restored from the model. Mouse modes and advanced graphics have separate cleanup. | `Session::erase` restores rows via `popup::erase`. Resize waits for cursor resynchronization and translates the tracked rectangle. | Track the preview rectangle separately and restore both regions from the same model. Recompute placement after resize, protecting prompt and input rows. |
| Upstream modifications | Preview hooks touch main, config, session, popup, keys, engine and exec. Provider, package, hidden-file and startup edits are also present in the same diff. | Completion and session state are centralized and testable without a UI framework. | Limit source hooks to module registration, config and Session. Keep layout, rendering, process handling, input framing and caching in the preview module. |

The old `sync_preview`/`poll_preview` pair guards against stale results. `stop_preview`, `reset_preview_visibility`, and resize callbacks cancel work and clear old resources. `handle_preview_key` routes shortcuts independently, with a pane-bound wheel handler. Preserve these mechanisms with a single generation-tagged worker per active preview session. Current Lig already multiplexes worker results, input, PTY output, resize events and timers on crossbeam channels. Its completion caches and history are independent of preview content, so the preview worker needs its own small LRU. Existing validation combines Rust tests with real-shell Python PTY tests.

The most likely rebase conflicts are in Session's draw/erase and event dispatch, where upstream shell and resize fixes land. A child module keeps preview-specific state and decisions outside the Session implementation. The Config field and parser validation and the main module declaration are low-risk. Cargo's dependency and lockfile changes need normal reconciliation. The image protocols use the same Session lifecycle and a preview-owned filter for terminal capability replies, while the cell renderer retains the existing restoration path.

## Implemented architecture

The session adapter converts a selected file or folder insertion into a local path with Lig's lexer and the completion request's working directory. Preview state is created when enabled, and the worker starts with the first visible target. One replaceable pending request and a generation counter keep obsolete work from publishing results. The worker applies category or extension rules, checks filesystem metadata and an in-memory LRU, and returns structured content. Cache keys include the resolved path, file stamp, relevant options and the actual dimensions for external responses. The selected file is rechecked every 500 ms while visible. Contextual Git previews refresh every two seconds, and native tree cache entries expire after two seconds so changes to nested entries are picked up.

The layout computes prompt protection from existing cwd and OSC 133 markers, vt100 scrollback and buffer snapshots. With an unverified prompt start, the rows above the edit buffer are treated as protected. If the unmodified list geometry would cover part of a known multiline prompt or wrapped edit buffer, the adapter asks the existing layout function for a placement outside those rows before showing both panels. The terminal overlay uses Lig's synchronized writes and cursor restoration. Mouse-reporting ownership lasts while a visible pane can consume it. A disabled preview adds no worker, file access or key interception.

Native backends use Syntect with the Two-Face grammars, Image's selected codecs, TAR and Flate2. Signature detection precedes extension lookup, including across the Windows path. BOM-marked UTF-16 is decoded before the binary-content check. Bounded EBML detection identifies WebM and Matroska files for configured media backends. The directory reader descends through three levels without following symlinks or junctions, and its rows use the completion icon resolver. Fallback modification times use the platform's locale formatting APIs. ZIP listings stream central-directory metadata using PKWARE's layout. The dev-only ZIP crate supplies independent fixtures. A bounded WebP preflight checks internal frame dimensions against the canvas and passes the exact validated RIFF range to the decoder. [Syntect syntax API](https://docs.rs/syntect/5.3.0/syntect/parsing/struct.SyntaxSet.html), [EBML specification](https://www.rfc-editor.org/rfc/rfc8794.html), [ZIP format specification](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT), [WebP container specification](https://developers.google.com/speed/webp/docs/riff_container).

Image previews share a bounded decode and cache. The worker prepares a PNG for Kitty or iTerm2 and a premultiplied RGBA thumbnail for the cell renderer. The cell renderer chooses a two-color mask for each group of four antialiased samples. The terminal adapter tracks a Kitty image ID or iTerm2 cell rectangle and clears it before repainting or restoring the preview. Capability probes do not block the session. Approval for Kitty inside tmux requires both the native probe reply and the attached client's `kittygraphics` feature. [Kitty graphics specification](https://sw.kovidgoyal.net/kitty/graphics-protocol/), [iTerm2 inline image specification](https://iterm2.com/documentation-images.html).

The external runner keeps the old process-group pattern and signal cleanup on Unix and starts subprocesses suspended on Windows until they join a kill-on-close Job Object. Preview pipes are polled with separate output bounds. The shell interpreter gets a literal script and the selected filename travels through the environment. The contextual Git adapter reads raw index or commit blobs and computes the worktree diff in Rust. Expanded floating diffs can use optional Delta with a unified fallback. Both commands run with paging disabled. Git and Delta receive fixed argv, and the preview never asks Git to apply repository diff drivers or worktree filters.

## Reference behavior and migration

The available older source supplied the split-pane technique, the SGR mouse framer and restoring mouse modes, generation-based job invalidation and the contextual Git behavior. The preview preserves keyboard and in-pane wheel scrolling, candidate changes, live reload, scroll across resize and signal cleanup. The configurable Alt+P shortcut controls visibility, Alt+F switches layout, and Alt+Z expands text-file previews in both dimensions or cycles image previews through the configured size and the 66% and 90% presets. The floating pane uses the right-hand corner with the most usable area and preserves its anchor when it shrinks. The layout choice lasts for the session and zoom resets on a new selection. Ctrl+P remains Lig's default previous-candidate key. With `show_on = "key_toggle"`, the completion list starts in its normal compact layout until the preview is explicitly opened.

An explicit inline pane uses a side placement and narrows the list only when it needs room. Automatic layout also permits stacked placements. The frame title can be disabled with `show_title = false`. Hidden preview scrolling keys pass through. Category backends and extension rules replace the older tool-specific handlers. An external command can provide a deeper tree or render video. Package previews require structured provider metadata that the upstream candidates lack. Remote completion candidates are excluded from local preview handling. The Kitty and iTerm2 writers preserve the older reference's bounded inline placement and selective cleanup. They use the native Rust raster from the preview worker.

## Upstream divergence

| Existing file | Change and reason | Rebase exposure and alternative |
|---|---|---|
| `src/main.rs` | One module declaration registers the subsystem. | Low. Equivalent module wiring would move the same declaration elsewhere. |
| `src/config.rs` | Two lines add the defaulted table and route validation through the existing diagnostics. | Low. A parallel parser would duplicate configuration loading and user error handling. |
| `src/session.rs` | About 75 lines attach a child adapter to session setup, worker events, input, prompt observations, draw and erase, resize and shutdown. The preview-enabled session sizes the bounded vt100 history for prompt tracking. | Moderate around the event loop and render/resize seams. Keeping policy in the child module leaves only calls in upstream code. An upstream overlay lifecycle hook could replace several of them. |
| `src/popup.rs` | Add a compact-height variant of the list geometry for constrained floating previews. It uses the existing list style and navigation. | Low. The normal geometry is restored on the next draw when space returns. |
| `Cargo.toml`, `Cargo.lock` | Add the bounded content engines, ANSI parser access and Windows Job Object, globalization and time APIs, with locked versions. | Low to moderate when overlapping dependency versions change. New crates are referenced only by the preview subsystem. |
| `README.md` | One link to the preview guide. | Low. The guide can move with the fork without code changes. |

New code lives in `src/preview/`. The dedicated PTY test is `tests/preview_pty.py`. Completion providers, the list renderer, the generator runner, PTY implementation, shell scripts and existing tests keep their current contracts.

## Validation scope and remaining limits

- macOS validation covers real Zsh and tmux PTYs. Fixtures check independent scrolling, image-to-archive transitions, progressive JPEG, UTF-16 text, tree icons and nested refresh, external placeholders, right and multiline prompt protection, shortcut behavior, inline width recovery and floating size presets across resize. They also check signal cleanup and restoration of earlier terminal output when the floating pane moves between the two right-hand corners.
- Linux and Windows builds were checked through their x86-64 target code paths, including test compilation. Target-native Linux and Windows execution, ConPTY mouse behavior and the Windows descendant-cleanup regression remain unverified on this host. The old checkout was reviewed in source and its own preview PTY suite was run against the supplied binary. The current fork has a separate suite that exercises the corresponding interactions under the new schema.
- The Windows runner requires a Job Object and falls back if assignment is unavailable. On Unix normal cancellation kills the preview process group. SIGTERM, SIGHUP, SIGINT and SIGQUIT enter the existing cleanup path while previews are enabled. A process that deliberately creates a separate session can outlive its group, and SIGKILL cannot run Unix cleanup.
- Large images outside the raster budget show metadata. Image placement uses terminal cell proportions when reported and a 1:2 estimate otherwise. The local tmux 3.7c build was exercised with the cell fallback. Native tmux capability selection and Kitty/iTerm2 protocol exchange were verified with simulated replies. The desktop automation environment blocked accessing Ghostty and iTerm2 windows, so graphical rendering and screen restoration in those apps remain unverified here.
- Native archive listings do not browse nested archives. ZIP entry names assume UTF-8 with replacement for malformed bytes. Encrypted central directories and multi-disk ZIP sets use fallback. Configured category and extension commands can use the installed 7-Zip CLI for additional archive formats and MediaInfo CLI for audio and video metadata.
- Visible previews poll file metadata. They refresh a changed document on the worker. Prompt tracking follows scroll shifts even after the bounded 256-row history fills. When terminal state cannot establish a protected interval, preview placement becomes conservative.
